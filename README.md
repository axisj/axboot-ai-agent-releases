# AXBOOT AI Agent Releases

AXBOOT AI Agent Releases 저장소는 AXBOOT AI 로컬 에이전트의 공개 배포 파일을 관리하는 공간입니다.

이 문서는 AXBOOT AI 소개와 함께, 에이전트를 설치하고 실제로 사용하는 방법을 단계별로 안내합니다.

## 1. AXBOOT AI 소개

AXBOOT AI는 AI-first 서비스 빌더 플랫폼으로, 사용자가 대화형 워크플로우를 통해 프로젝트를 생성하고 수정하며 배포 준비까지 진행할 수 있도록 설계되어 있습니다.

핵심 개념:

- Project(내부 용어: Workspace): 하나의 배포 가능한 서비스 단위
- Chat Session: AI와의 작업 과정(대화, 의도, 진행 상태)
- Version: 결과 스냅샷(불변)

AXBOOT AI Agent는 데스크톱 환경에서 다음 역할을 수행합니다.

- 로컬 프로젝트 부트스트랩
- 개발 런타임 실행/상태 점검
- 서버와의 안전한 통신(WebSocket 기반)
- 코드 패치/적용 보조

## 2. 이 저장소 구조

- `releases/`: 버전별 배포 산출물
- `.github/workflows/promote-latest-prerelease.yml`: 최신 공개 프리릴리즈를 latest 릴리즈로 승격하는 수동 GitHub Actions 워크플로
- `README.md`: 소개 및 사용 설명서(현재 문서)

## 3. 사전 준비

운영체제별 기본 준비 사항:

- macOS / Windows / Linux 중 1개
- 압축 파일 해제 도구(zip)
- 인터넷 연결(초기 인증/통신 시 필요)

권장:

- 최신 안정 버전 OS 사용
- 사내 보안 솔루션 사용 시 에이전트 실행 파일 예외 정책 사전 확인

## 4. 설치 방법

1. `releases/` 디렉터리에서 운영체제에 맞는 최신 릴리스 파일을 다운로드합니다.
2. 압축 파일을 원하는 위치에 해제합니다.
3. 실행 파일을 실행합니다.

운영체제별 실행 예시:

- macOS: `.app` 실행 (최초 실행 시 보안 경고가 나오면 시스템 설정에서 허용)
- Windows: `.exe` 실행
- Linux: 실행 권한 부여 후 바이너리 실행

Linux 권한 부여 예시:

```bash
chmod +x ./AXBOOT-AI-Agent
./AXBOOT-AI-Agent
```

## 5. 빠른 시작

1. 에이전트 실행
2. 로그인 또는 디바이스 인증 진행
3. 연결할 Project 선택
4. AI 채팅/작업 화면에서 지시 실행
5. Preview로 결과 확인 후 Apply

권장 워크플로우:

- 먼저 작은 변경(문구 수정, UI 일부 수정)으로 연결 상태 확인
- 이후 구조 변경/대규모 생성 작업 수행

## 6. 사용 설명서

### 6.1 프로젝트 연결

- 기존 프로젝트 연결: 로컬 경로 선택 후 메타데이터 로드
- 신규 프로젝트 생성: 템플릿/생성 옵션 선택 후 초기 구조 생성

### 6.2 AI 작업 수행

- 자연어로 작업 요청(예: "로그인 페이지를 반응형으로 개선")
- 작업 단위를 명확히 분리하여 요청(한 번에 한 목표)
- 생성된 변경은 Preview에서 먼저 검토

### 6.3 Preview와 Apply

- Preview: 실제 적용 전 변경 결과를 확인
- Apply: 검토가 끝난 변경만 명시적으로 반영

중요:

- 실서비스 반영 전에는 반드시 Preview를 통해 UI/동작 검증
- 큰 변경은 단계별 Apply를 권장

### 6.4 버전 관리 권장 방식

- 의미 있는 작업 단위로 커밋
- 릴리스 전 체크리스트(빌드, 린트, 핵심 시나리오 점검) 수행

## 7. 업데이트 방법

1. 최신 릴리스 파일 다운로드
2. 기존 에이전트 종료
3. 새 버전으로 교체 후 실행
4. 실행 후 버전 정보 확인

주의:

- 업데이트 전 현재 작업 상태를 저장
- 중요 프로젝트는 업데이트 전 백업 권장

## 8. latest 릴리즈 승격

GitHub Actions의 `Promote latest prerelease` 워크플로를 수동 실행하면 GitHub Releases에 있는 공개 프리릴리즈 중 SemVer 기준 최신 태그를 latest 릴리즈로 승격합니다.

동작 방식:

- draft 릴리즈는 제외합니다.
- `vX.Y.Z` 형식의 공개 프리릴리즈만 대상으로 합니다.
- 선택된 릴리즈를 `draft: false`, `prerelease: false`, `make_latest: true`로 업데이트합니다.
- 특정 태그만 승격하려면 워크플로 입력값 `tag`에 태그명을 넣습니다.
- 실제 변경 없이 대상만 확인하려면 `dry_run`을 켭니다.

## 9. 문제 해결

### 실행이 차단되는 경우

- macOS: 시스템 설정 > 개인정보 보호 및 보안에서 실행 허용
- Windows: SmartScreen 경고 시 파일 출처 확인 후 실행

### 서버 연결이 안 되는 경우

- 네트워크/VPN/방화벽 상태 확인
- 조직 보안 정책으로 WebSocket이 차단되지 않았는지 점검
- 에이전트 재시작 후 재시도

### 프로젝트 로드 실패

- 경로 권한 확인
- 손상된 프로젝트 폴더 여부 확인
- 최소 샘플 프로젝트로 재현 테스트

## 10. 보안 가이드

- 인증 토큰/비밀키를 저장소에 커밋하지 않습니다.
- 공유 PC에서는 작업 후 로그아웃합니다.
- 배포 파일은 공식 릴리스 경로에서만 다운로드합니다.
